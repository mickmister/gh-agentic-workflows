# Runtime status

Spec Kit and its pinned Pi integration are the only supported execution path.
See [the hosted runtime](../../../../.github/qrspi-hosted/README.md) and
[Spec Kit](../../../../.github/qrspi-spec-kit/README.md) for current capabilities,
installation pins, entry points and qualification limits.

The old document pilot, alternate transports, native formulas/packs and legacy
coding launchers are removed. Historical receipts and source revisions retain
their original meaning; they are not runnable compatibility modes. Only explicitly
Spec Kit workspace checkpoints can resume, without implicit migration or replay.

The production QRSPI path is source-disabled. Shared source capabilities and the
disposable multi-agent smoke do not establish general source-development dispatch.
The separate setup specialist runs a scoped Spec Kit workflow. Broader coding and
evidence-fed exit interviews remain independently tracked work.

The host validates authenticated exact-pinned review responses. Private S3
read/check/PUT/readback admission remains best-effort, not atomic CAS. Unknown
effects require reconciliation. Inspection and assessment are evidence projection,
not phase approval or authority to replay.

Only trusted parent/runner-designated orchestrators may delegate. Worker tool
surfaces enforce scoped capabilities; prose alone does not establish OS isolation.
QRSPI owns methodology gates. Review procedures remain provisional pending the
task-z5a human and installed-extension acceptance work.
